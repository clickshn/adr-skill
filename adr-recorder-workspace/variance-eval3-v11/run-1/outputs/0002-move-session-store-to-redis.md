# ADR-0002: 세션 저장소를 프로세스 메모리에서 Redis로 이전

- **Status:** Proposed
- **Date:** 2026-09-14
- **Decision:** 세션 저장소를 애플리케이션 프로세스 메모리에서 공유 Redis로 옮긴다.
- **Scope:** member-portal
- **Decision Source:** Human

---

## Context

### Problem

- 세션 데이터를 애플리케이션 프로세스 메모리(`app/session.py`의 모듈 전역 dict)에 보관하고 있어 프로세스 간 공유가 되지 않는다.
- 서버를 3대로 늘린 뒤, 로그인한 사용자의 후속 요청이 세션을 만든 인스턴스가 아닌 다른 인스턴스로 라우팅되면 세션을 찾지 못해 로그인이 풀리는 문제가 발생했다.
- 프로세스 메모리 방식은 재시작·재배포 때마다 세션이 전부 사라진다.

### Constraints

- 기존 로그인/로그아웃 API(커밋 `bd074f7`)의 동작과 `app/session.py`의 `get`/`put` 인터페이스를 유지해야 한다.
- 현재 스택은 FastAPI + uvicorn + SQLAlchemy이며, `redis==5.0.8`이 `requirements.txt`에 이미 추가되어 있다.
- 서버 3대 구성은 이미 확정된 전제다.

## Decision

### Selected

- **Technology:** Redis (`redis==5.0.8`, requirements.txt에 추가됨)
- **Architecture:** 세션 저장소를 프로세스 로컬 인메모리 dict에서 분리해, 3대 인스턴스가 함께 바라보는 외부 Redis에 둔다. 애플리케이션 인스턴스는 세션에 대해 stateless가 된다.
- **Implementation:** `app/session.py`의 `get`/`put`을 Redis 클라이언트 기반 구현으로 교체하고, 호출부가 바뀌지 않도록 기존 함수 시그니처를 유지한다. 세션 키 접두사·직렬화 방식·TTL을 함께 정의한다.

## Rationale

1. 세션을 프로세스 밖 공유 저장소로 옮기면 어느 인스턴스가 요청을 받아도 같은 세션을 조회할 수 있어, 서버 증설로 발생한 로그인 유실이 직접 해소된다.
2. 인스턴스가 세션 상태를 들고 있지 않게 되어, 이후 증설·재배포·인스턴스 교체에서 같은 문제가 재발하지 않는다.
3. Redis는 키 단위 만료(TTL)를 기본 제공하므로 세션 수명 관리를 애플리케이션에서 따로 구현하지 않아도 된다.
4. 의존성이 이미 추가되어 있어 도입에 필요한 남은 작업이 `app/session.py` 교체와 접속 설정으로 한정된다.

## Alternatives

### 현행 유지 (프로세스 메모리 dict)

- **Pros:** 추가 인프라와 운영 부담이 없고, 조회에 네트워크 왕복이 없으며 구현이 가장 단순하다.
- **Cons:** 프로세스 간 세션 공유가 불가능하고, 재시작 시 세션이 모두 소실된다.
- **Rejected because:** 서버를 3대로 늘린 구성에서 인스턴스 간 세션이 공유되지 않아 로그인이 풀리는 문제가 실제로 발생했다.

## Consequences

### Positive

- 3대 인스턴스 중 어디로 요청이 가도 로그인 세션이 유지된다.
- 애플리케이션 재시작·재배포 후에도 세션이 유지된다.
- 인스턴스가 stateless가 되어 추가 증설이나 롤링 배포가 쉬워진다.

### Negative

- 운영·모니터링해야 할 인프라 구성 요소(Redis)가 하나 늘어난다.
- 세션 조회마다 네트워크 왕복이 생겨 요청 지연이 소폭 증가한다.
- Redis 접속 정보·자격 증명 등 관리해야 할 설정 항목이 늘어난다.

### Risks

- Redis가 단일 장애점이 된다. 장애 시 3대 전부에서 로그인이 동작하지 않는다.
- 기존 프로세스 메모리 세션은 이전되지 않으므로, 전환 배포 시점에 로그인 중이던 사용자는 한 번 로그아웃된다.
- 직렬화 방식·키 네이밍·TTL을 명확히 정하지 않으면 인스턴스 간 세션 해석이 어긋날 수 있다.

## Implementation

- [ ] `app/session.py`의 `get`/`put`을 Redis 기반으로 교체 (키 접두사, 직렬화, TTL 정의 포함)
- [ ] 서로 다른 인스턴스로 요청이 분산돼도 세션이 유지되는지 통합 테스트 추가
- [ ] Redis 가용성·응답 지연·메모리 사용량 모니터링 추가
- [ ] Redis 접속 설정(환경변수)과 3대 서버 배포 문서 업데이트

## Reversibility

- **Reversible:** Yes
- **Rollback:** `app/session.py`를 커밋 `bd074f7` 시점의 인메모리 dict 구현으로 되돌리고 `requirements.txt`에서 `redis==5.0.8`을 제거한다. 다만 롤백하면 서버 3대 구성에서 로그인 유실 문제가 그대로 재발한다.
- **Migration Cost:** Low
