# ADR-0002: 세션 저장소를 프로세스 메모리에서 Redis로 이전

- **Status:** Proposed
- **Date:** 2026-09-14
- **Decision:** 세션 데이터를 프로세스 메모리 딕셔너리 대신 공유 Redis에 저장한다.
- **Scope:** member-portal
- **Decision Source:** Human

---

## Context

### Problem

- 세션이 `app/session.py`의 프로세스 메모리 딕셔너리(`_sessions`)에 보관되어, 세션이 그 세션을 만든 서버 프로세스 안에만 존재한다.
- 애플리케이션 서버를 3대로 늘리면서, 요청이 세션을 만든 서버가 아닌 다른 서버로 라우팅되면 세션을 찾지 못해 로그인이 풀리는 문제가 발생했다.
- 프로세스 재시작 시에도 세션이 전부 사라진다.

### Constraints

- 기존 스택은 FastAPI 0.112.2 / uvicorn 0.30.6 / SQLAlchemy 2.0.32이며, 세션 저장소만 교체한다.
- 서버 3대가 동일한 세션을 읽고 쓸 수 있어야 한다.

## Decision

### Selected

- **Technology:** redis 5.0.8 Python 클라이언트 (`requirements.txt`에 이미 추가됨)
- **Architecture:** 서버 3대가 공유하는 외부 Redis 인스턴스를 세션 저장소로 사용하고, 애플리케이션 프로세스는 세션 상태를 들고 있지 않는다.
- **Implementation:** `app/session.py`의 `get`/`put`을 Redis 조회/저장으로 교체한다. 현재 인터페이스는 이 두 함수뿐이라 호출부 변경 없이 내부 구현만 바꾼다.

## Rationale

1. 세션을 프로세스 밖 공유 저장소로 옮기면 어느 서버가 요청을 받아도 같은 세션을 조회할 수 있어, 서버 증설로 생긴 로그인 풀림의 원인이 제거된다.
2. 세션 접근이 `app/session.py`의 `get`/`put` 두 함수로 캡슐화되어 있어 교체 범위가 한 파일에 한정된다.
3. 세션이 프로세스 수명과 분리되므로 배포·재시작 시에도 로그인이 유지된다.

## Alternatives

### 프로세스 메모리 세션 유지 (현행)

- **Pros:** 추가 인프라와 의존성이 없고, 구현이 이미 존재하며 네트워크 왕복이 없다.
- **Cons:** 서버 간 세션 공유가 불가능하고, 프로세스 재시작 시 세션이 소실된다.
- **Rejected because:** 서버 3대 환경에서 로그인이 풀리는 원인 그 자체이므로, 이번 문제를 해결하지 못한다.

## Consequences

### Positive

- 서버 3대 중 어디로 요청이 가도 로그인 상태가 유지된다.
- 앱 프로세스가 무상태가 되어 서버를 추가로 늘리거나 재배포하기 쉬워진다.

### Negative

- Redis 인스턴스라는 운영 대상이 새로 생기고, 접속 정보 설정과 배포 환경 구성이 필요하다.
- 세션 조회마다 네트워크 왕복이 추가된다.

### Risks

- Redis가 단일 장애점이 된다. Redis 장애 시 전체 로그인이 영향을 받는다.
- 세션 직렬화 형식과 만료(TTL) 정책을 새로 정해야 하며, 정하지 않으면 세션이 무한히 쌓인다.
- 전환 시점에 메모리에 남아 있던 기존 세션은 이관되지 않아 사용자가 한 번 다시 로그인해야 한다.

## Implementation

- [ ] `app/session.py`의 `get`/`put`을 Redis 기반 구현으로 교체하고 세션 TTL을 설정
- [ ] 서버 3대 환경에서 요청이 서버 간을 오갈 때 로그인이 유지되는지 테스트
- [ ] Redis 연결 실패·지연 및 세션 키 증가량 모니터링
- [ ] Redis 접속 정보(호스트/포트/인증)를 환경 설정으로 분리하고 배포 문서 갱신

## Reversibility

- **Reversible:** Yes
- **Rollback:** `requirements.txt`에서 `redis==5.0.8`을 제거하고, `app/session.py`를 커밋 83bb4e5에 있는 프로세스 메모리 딕셔너리 구현으로 되돌린다. 되돌리면 진행 중인 세션은 유실되고, 서버 3대 환경의 로그인 풀림 문제가 다시 나타난다.
- **Migration Cost:** Low
