**ADR-0002: 세션 저장소를 프로세스 메모리에서 Redis로 이전**

- **Status: Proposed** — requirements.txt에 redis가 이미 추가돼 있지만, 기존 결정 로그 이관이 아니라 새로 내리는 결정이라 Proposed로 시작했습니다. 확정되면 Accepted로 바꿔주세요.
- **Context** — `app/session.py`의 모듈 전역 dict(`_sessions`)가 프로세스 지역 상태라서, 3대로 늘린 뒤 세션을 만든 서버가 아닌 곳으로 요청이 가면 미인증 처리되는 구조를 문제로 정리했습니다.
- **Decision** — redis 5.0.8을 쓰고, `get`/`put` 시그니처는 유지한 채 구현체만 Redis 클라이언트로 교체하는 방향으로 적었습니다.
- **Reversibility** — 롤백 기준점은 `app/session.py`의 메모리 구현이 실제로 들어있는 **69b2c22**로 잡았습니다. HEAD인 ba84cb2("로그인/로그아웃 API")는 `git show --stat`으로 확인해 보니 파일 변경이 없는 빈 커밋이라 인용 대상에서 뺐습니다.

두 가지 참고해주세요.

1. **Alternatives에 "현행 유지(프로세스 메모리)" 하나만 들어가 있습니다.** 말씀하신 내용에서 기각 근거가 분명한 대안이 그것뿐이라 추측으로 채우지 않았습니다. 혹시 Memcached, DB 세션 테이블, 스티키 세션, JWT 같은 선택지를 검토하고 접으셨다면 기각 사유와 함께 알려주시면 섹션에 추가하겠습니다.
2. **Review Trigger 섹션은 만들지 않았습니다.** 재검토 조건으로 삼을 만한 얘기가 대화에 없어서인데, "Redis 운영 비용이 X 이상이 되면" 같은 조건이 있으면 넣어드리겠습니다.

그리고 실측 수치(로그인 풀림 발생률, 세션 조회 지연 등)가 없어서 Evidence 섹션도 생략했습니다. 나중에 측정값이 나오면 채워 넣으면 됩니다.

ADR 파일 외에는 아무것도 건드리지 않았습니다.
