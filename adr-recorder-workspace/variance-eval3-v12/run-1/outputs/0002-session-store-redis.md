# ADR-0002: 세션 저장소를 프로세스 메모리에서 Redis로 이전

- **Status:** Proposed
- **Date:** 2026-09-14
- **Decision:** 세션 저장소를 프로세스 메모리 dict에서 외부 Redis로 옮긴다.
- **Scope:** member-portal
- **Decision Source:** Human

---

## Context

### Problem

애플리케이션 서버를 3대로 늘리면서 로그인이 임의로 풀리는 문제가 발생했다. 현재 세션은
`app/session.py`의 모듈 전역 dict(`_sessions`)에 보관되어 프로세스 안에서만 유효하다.
요청이 세션을 만든 서버가 아닌 다른 서버로 분산되면 해당 세션을 찾지 못해 미인증으로
처리된다.

### Constraints

- 서버 인스턴스는 3대이며, 요청이 특정 인스턴스에 고정된다는 보장이 없다.
- 세션은 프로세스 재시작·인스턴스 교체와 무관하게 모든 인스턴스에서 동일하게 조회되어야 한다.
- 기존 세션 접근은 `get`/`put` 두 함수로만 이루어져 호출부 변경 없이 구현체 교체가 가능하다.

## Decision

### Selected

- **Technology:** Redis (`redis==5.0.8`, requirements.txt에 추가됨)
- **Architecture:** 애플리케이션 프로세스 외부의 공유 세션 저장소. 3대의 서버가 동일한
  Redis 인스턴스를 바라보며 세션 상태를 공유한다.
- **Implementation:** `app/session.py`의 `get`/`put`을 Redis 클라이언트 기반 구현으로 교체한다.
  함수 시그니처는 유지해 호출부는 수정하지 않는다.

## Rationale

1. 로그인이 풀리는 원인은 세션이 프로세스 지역 상태라는 점이므로, 프로세스 밖의 공유
   저장소로 옮기는 것이 원인을 직접 제거한다.
2. 세션 접근 지점이 `get`/`put` 두 함수로 좁혀져 있어 저장소 교체 비용이 낮다.
3. Redis는 TTL을 저장소 차원에서 지원해 세션 만료 처리를 애플리케이션에서 따로 관리하지
   않아도 된다.

## Alternatives

### 현행 유지 (프로세스 메모리 dict)

- **Pros:** 외부 의존성이 없고 추가 운영 요소가 생기지 않는다. 조회 지연이 사실상 없다.
- **Cons:** 세션이 인스턴스마다 따로 존재해 수평 확장과 양립하지 않는다. 프로세스가 재시작되면
  세션이 모두 사라진다.
- **Rejected because:** 서버를 3대로 늘린 뒤 로그인이 풀리는 문제를 일으킨 원인 그 자체다.

## Consequences

### Positive

- 어느 인스턴스로 요청이 가든 동일한 세션이 조회되어 로그인 풀림 현상이 해소된다.
- 인스턴스를 추가·재시작해도 세션이 유지되어 배포와 확장이 자유로워진다.

### Negative

- Redis라는 운영 구성요소가 새로 추가된다(프로비저닝, 접속 정보 관리, 모니터링 대상 증가).
- 세션 조회가 프로세스 내 dict 접근에서 네트워크 왕복으로 바뀐다.

### Risks

- Redis가 단일 장애점이 된다. 다운되면 전체 로그인이 불가능해진다.
- 세션 데이터가 프로세스 경계를 넘어가므로 직렬화 형식과 TTL 정책을 명시적으로 정해야 한다.
- 접속 정보가 코드/설정에 노출되지 않도록 관리해야 한다.

## Implementation

- [ ] `app/session.py`의 `get`/`put`을 Redis 클라이언트 구현으로 교체 (시그니처 유지)
- [ ] 세션 직렬화 형식과 TTL 정책 결정 및 적용
- [ ] Redis 접속 설정을 환경변수로 분리
- [ ] 3대 인스턴스 환경에서 교차 요청 로그인 유지 테스트
- [ ] Redis 연결 실패·지연에 대한 모니터링 및 알림 추가
- [ ] 배포 문서에 Redis 의존성 및 접속 설정 항목 추가

## Reversibility

- **Reversible:** Yes
- **Rollback:** requirements.txt에서 `redis==5.0.8`을 제거하고 `app/session.py`를 69b2c22에
  도입된 프로세스 메모리 dict 구현으로 되돌린다. 저장된 세션은 버려지고 사용자는 재로그인한다.
  단, 롤백하면 3대 구성에서 로그인이 풀리는 원래 문제가 그대로 재현된다.
- **Migration Cost:** Low
