ADR을 `docs/adr/0002-move-session-store-to-redis.md`로 썼어요. 기존 ADR-0001과 같은 헤더 형식이고, 상태는 Accepted, 결정 주체는 Human으로 적었습니다.

**ADR에 적은 내용**
- **배경:** 세션이 `app/session.py`의 프로세스 메모리 dict에만 있어서, 서버를 3대로 늘리자 다른 서버로 요청이 가면 로그인이 풀렸음
- **결정:** 모든 서버가 함께 쓰는 Redis에 세션 저장, `redis==5.0.8` 추가. `get`/`put` 인터페이스는 그대로 두고 내부만 교체
- **결과:** 좋아지는 점은 서버를 늘려도, 재배포해도 세션이 유지되고 sticky session이 필요 없다는 것. 대신 운영할 컴포넌트가 늘고 Redis가 인증 경로의 단일 장애점이 됨. 세션 값은 직렬화해야 하고 TTL 정책도 새로 정해야 함. 전환 시점에 기존 세션은 옮겨지지 않아 한 번 다시 로그인해야 함
- **대안:** sticky session, DB 세션 테이블, JWT

**확인해 주세요**
1. 알려주신 건 서버 3대와 redis 추가뿐이라, TTL·Redis 배포 형태·장애 시 동작 같은 구체적인 값은 지어내지 않고 ADR 끝의 **Open Questions**에 남겨뒀어요. 정해지면 알려주세요, 채워 넣을게요.
2. **대안** 절의 세 가지와 기각 이유는 제가 쓴 초안이에요. 팀이 실제로 검토한 내용과 다르면 고쳐 주세요.

`app/session.py`는 아직 메모리 dict 그대로이고, 이번에는 ADR만 추가했어요. Redis 구현이 필요하면 말씀해 주세요.
